# I/O That Parks Only the Goroutine

Every `sched` procedure that waits parks only the calling goroutine; the others keep running on the same thread. That covers I/O too:

| Procedures | For |
|---|---|
| `listen_tcp`, `accept`, `dial`, `send(socket, buf)`, `recv(socket, buf)`, `close(socket)`, `send_file` | TCP |
| `udp_socket`, `bind`, `send_to`, `recv_from`, `close(socket)` | UDP |
| `wait_ready(socket, .Receive)` / `.Send` | waiting until a socket is readable or writable |
| `open`, `read_at`, `write_at`, `stat`, `close(file)`, `read_entire_file`, `write_entire_file` | files |
| `resolve("host:port")` | DNS lookups |
| `blocking(proc[...]() { ... })` | anything else that blocks the thread |

Sockets and timers go through `core:nbio`: io_uring on Linux, kqueue on macOS, IOCP on Windows. When no goroutine can run, the scheduler waits in the event loop until one can. Files use io_uring on Linux and worker threads elsewhere, and DNS lookups always use a worker thread.

## An Echo Server

```vidar
import "vidar:sched"

echo :: proc(client: net.TCP_Socket) {
	buf: [256]byte
	for {
		n, err := sched.recv(client, buf[:])
		if err != nil || n == 0 do break
		sched.send(client, buf[:n])
	}
	sched.close(client)
}

main :: proc() {
	listener, err := sched.listen_tcp({net.IP4_Loopback, 8080})
	if err != nil {
		fmt.println("listen failed:", err)
		return
	}
	for {
		client, _, aerr := sched.accept(listener)
		if aerr != nil do return
		sched.go(proc[client]() { echo(client) })      // one goroutine per client
	}
}
```

## `blocking`: Calls That Block the Thread

Plain blocking calls, such as `os.read` on a pipe, `time.sleep`, a C library's network call or `core:sync`'s locks, block the whole thread, and with it every goroutine on it. Use the `sched` version where there is one. Where there isn't, wrap the call in `sched.blocking`, which runs a closure on a worker thread and parks the calling goroutine until it's done:

```vidar
import "vidar:sched"

main :: proc() {
	result := 0
	sched.blocking(proc[&result]() {
		time.sleep(10 * time.Millisecond)     // blocks a worker thread, not the scheduler
		result = 42
	})
	fmt.println(result)
}
```

```output
42
```

- When no other goroutine is runnable or waiting on I/O, `blocking` runs the closure inline instead, since nothing could run in the meantime. A program that calls it only at startup never starts the workers.
- The closure runs on another thread, with the goroutine's `context` but that thread's temp allocator. It must not touch state other goroutines use without synchronizing, and `context.allocator` must be thread-safe (the default heap allocator is).
- There are 4 worker threads; `-define:VIDAR_WORKERS=<n>` changes that.
